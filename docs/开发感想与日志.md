> 作者：清华计算机系（贵系）学生
> 这是从"只会用库"到"敢手搓大模型"的一段记录，写给未来的自己，也写给可能看到这份代码的人。

## 缘起

一开始这个仓库只是随手丢代码的地方——训练脚本、量化策略、一堆 HTML，文件名还带着 `V14`、`V21quant Model.py`、`transformer_O-O.py` 这种随手起的名字，README 和实际文件完全对不上。

真正让我想认真做下去的是一个问题：**如果只靠调用现成 API，我永远只是在"用"大模型，而不是在"懂"大模型。** 于是决定从零把 Transformer 写一遍，再一步步把推理优化的整条链路走通。

---

## 一路走来的几个阶段

### 1. 从零实现 Transformer
字符级的 `CharTransformer`，把 Embedding、多头注意力、位置编码、训练循环、生成采样（Top-K/Top-P/温度）、RAG、INT8 量化全部自己写。这一步最大的收获是：**模型不是魔法，是一堆矩阵乘法和可导的损失函数。**

### 2. 工程化改造
后来把仓库整理成规范结构：`src`/`大模型` 分目录、`pyproject.toml`、CI（ruff + pytest + 编译冒烟）、`.gitignore`、MIT LICENSE。**代码能跑和代码能维护是两回事。** 这段让我体会到大厂工程的"专业感"从哪来——不是炫技，是纪律。

### 3. 推理优化主线（最有成就感的一段）
从零手搓了一个 decoder-only GPT，然后一路优化：

- **KV Cache**：解码从每步重算整个上下文，变成每步 O(1) 追加。第一次跑出 3.6× 加速时，理解了为什么"预填充"和"解码"要分开。
- **量化对比**：INT8/INT4/FP8 权重压缩 4–5×，PPL 几乎不变。原来"小一点"也可以"一样好"。
- **投机解码**：小模型当"草稿"，大模型一次并行验证。修了两个隐蔽 bug（目标概率取错位、bonus token 没进 KV 缓存）后，测试锁死了"draft==target 时输出完全一致"。那一刻真的理解了**正确性要靠测试证明，不能靠感觉**。
- **连续批处理**：给 batch 里的请求做动态 slot 复用。虽然 CPU 小模型上它没干过静态批处理（诚实地说），但**正确性验证（输出==逐条解码）是实打实的**，也让我明白了 PagedAttention 为什么是显存的关键。

### 4. 量化交易
聚宽平台的随机森林、XGBoost+SHAP、动态风控。这一块让我学会了：**策略写得再漂亮，回测的坑（未来函数、过拟合、幸存者偏差）一个都躲不掉。**

### 5. 网页与游戏
《陈深的世界》系列互动游戏——单文件 HTML、清华紫黑风格、图片走 CDN。做网页时最深的体会：**"能用"和"好看"之间，差的是一整套审美和细节。**

## 踩过的坑（希望你别再踩）

1. **文件名别乱起**：`V21quant Model.py`（带空格）差点让 import 崩溃。统一 snake_case。
2. **API Key 别硬编码**：`DEEPSEEK_API_KEY = "sk-"` 这种直接进仓库是事故，一律走环境变量。
3. **KV Cache 的掩码**：decode 阶段不能直接复用 prefill 的下三角掩码，否则只看到第一个 key。
4. **投机解码的目标概率**：`logits[i]` 预测的是候选 i **后面**那个 token，判定接受要取对位置。
5. **量化要量化 PPL 变化**：别只看"压缩了多少倍"，要看"质量掉了多少"。
6. **别碰会断的引用**：`photos/` 被 CDN 链接直接引用，改名就断图。

## 感想

写完这一整套，最想说的是三句：

- **"从零实现"是最好的学习方式。** 用一次库，你会用；写一次，你才懂。
- **数字比口号有说服力。** README 里写"优化了推理"没人信，放一张"3.6× 加速、PPL 不变"的表，所有人都会信。
- **工程能力=把事做对的纪律。** CI、测试、文档、命名规范，这些不炫但撑起一个项目。

我依旧还有很多不会的——真正的 distributed training、PagedAttention、生产级 serving。但至少，我现在敢说：**我知道一个模型从训练到上线要过哪些坎，而不是只会调 API。**
