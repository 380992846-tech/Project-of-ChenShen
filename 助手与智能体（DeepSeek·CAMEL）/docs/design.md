# 🧠 设计决策

记录关键取舍与理由，便于后续维护与评审。

## 1. `src/` 布局 + 单一 package

- **为何**：把"可复用包"与"脚本"区分开；`src` 布局强制消费者从已安装的包导入，而非依赖脚本目录路径。
- **权衡**：多一层目录；换来更干净的导入与打包语义。

## 2. 集中配置 + `.env` + 校验

- **为何**：密钥只从环境读，绝不入库；`validate()` 在启动即失败，给出可操作提示，而不是运行到一半才报错。
- **权衡**：需要用户提供 `.env` 或环境变量；换来回滚/审计友好、跨环境一致。

## 3. 依赖懒加载（openai / edge-tts / camel-ai）

- **为何**：`camel-ai` 重且易变；把第三方依赖做成可选，保证**包本身永远可导入**、测试零三方依赖。
- **权衡**：使用对应能力时需自行安装；在首次调用时给明确错误提示（`请 pip install camel-ai`）。

## 4. 记忆：线程安全 + 原子写

- **为何**：语音播报/交互不会阻塞主循环，但写入可能并发；`os.replace` 保证崩溃也不留下半截 JSON。
- **权衡**：每次写入都全量序列化（小数据规模下可接受）；换来"永不损坏"的强一致。

## 5. LLM：超时 + 指数退避重试

- **为何**：网络/限流抖动不可避免；重试 + 日志能显著提升可用性且可观测。
- **权衡**：可能增加延迟；用「最多 N 次 + 指数退避」同时避免无限重试。

## 6. CLI 用 argparse 而非 Typer

- **为何**：零额外依赖、零学习成本、跨版本稳定。
- **权衡**：少一些花哨的自动补全/帮助；本项目命令足够简单，不值得引入依赖。

## 7. 记忆默认用户级目录（`~/.dsh_assistant`）

- **为何**：对话历史属个人状态，不该进 git；用户级目录避免污染仓库、也不会在 CI 里残留。
- **权衡**：需用 `DSH_DATA_DIR` / `--history-file` 覆盖时多一步配置。

## 8. 可测试 + CI

- **为何**：配置/记忆/提示词无网络、无三方依赖即可单测；CI 保证回归。
- **权衡**：需维护测试；换来可持续演进。
