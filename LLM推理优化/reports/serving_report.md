# 并发/批量 serving 基准

- 模型参数：`187,328`；请求数 `48`，prompt `16`，生成 `32`，`3` 轮平均

| batch size | 吞吐 (tokens/s) | P50 (ms) | P99 (ms) |
|-----------|-----------------|----------|----------|
| 1 | 269.5 | 119.3 | 213.3 |
| 4 | 956.4 | 143.3 | 212.2 |
| 8 | 2092.9 | 129.3 | 139.6 |
| 16 | 4379.0 | 115.9 | 136.0 |

## 结论
- 增大 batch 显著提升吞吐（摊销单步前向固定开销）；
- 代价是单请求延迟上升（吞吐-延迟权衡）——这正是 serving 系统要平衡的指标；
- 真实系统（vLLM/TGI）在此基础上做 **continuous batching** 与 `PagedAttention` 以进一步压延迟、提利用率。
