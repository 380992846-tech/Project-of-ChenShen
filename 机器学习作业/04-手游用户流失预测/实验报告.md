# 某闯关类手游用户流失预测 —— 实验报告

## 一、问题描述与目标

休闲闯关类手游新用户流失严重。公司在用户尚未完全卸载前若能识别出流失风险较高的用户并给予干预（如奖励道具、暖心短信），就能挽回用户、提升活跃度与收益。

本作业目标：基于 2020.2.1 注册用户在前四日（2.1–2.4）的真实游玩日志，**预测测试集每个用户是否为流失用户（二分类）**。流失定义为**次周（2.7–2.13）未登录**。评价指标为 **AUC**，要求达到 0.65 以上。

## 二、数据说明与观察（EDA）

数据共 5 个文件（另附测试集真实标签 `Groundtruth.csv`，仅用于本地校验，不参与训练）：

| 文件 | 说明 |
|---|---|
| `train.csv` / `dev.csv` | 训练/验证集：`user_id` 与 `label`（1=流失，0=留存），用户两两不重叠 |
| `test.csv` | 测试集：仅 `user_id`，需预测流失概率 |
| `level_seq.csv` | 核心日志：一行 = 用户对某关的一次尝试（`f_success` 通关、`f_duration` 用时、`f_reststep` 剩余步数比、`f_help` 是否用道具/提示、`time` 时间戳）|
| `level_meta.csv` | 关卡统计：平均用时、通过率、通关用时、平均重试次数 |

**关键观察：**
- 样本量：训练 8158、验证 2658、测试 2773，共 13589 个用户，**所有用户均有游玩日志**（无缺失匹配）。
- 流失比例：训练集约 33.5%，dev 与 Groundtruth 均约 34%。
- 游玩规模：人均尝试约 161 次（中位数 108），用户差异大（最活跃者 4122 次）；通关约 116 万次、失败约 103 万次，道具/帮助使用约 9.7 万次。
- `time` 覆盖 2.1–2.4 整个观测窗口，可用于刻画活跃节奏与衰减。

**流失 vs 留存的行为差异**（对训练集按标签分组比较特征均值）：流失用户的游玩总量、通关率、到达关卡进度显著更低，道具使用率更高，"最后活跃距观测窗口结束的时间"明显更长。这与"早期流失源于活跃度下降、卡关挫败与道具依赖"的业务直觉一致。

## 三、方案设计

整体采用"**特征工程 + 表格机器学习模型 + 集成**"路线，分四步：

### 3.1 特征工程
以 `user_id` 为粒度，对非结构化 `level_seq` 进行聚合，得到"每用户一行"的 43 维特征，分为 6 大类：

1. **基础活跃度**：总尝试次数、总时长、活跃天数、每日尝试量（前 4 天）、活跃小时数、最后活跃距观测结束时间、日均尝试数。
2. **通关能力与进度**：通关数/率、到达的最高关卡、通过的不同关卡数、首通最高关卡、进度率。
3. **重试行为**：平均每关尝试次数、单关最多尝试次数、被重试的关卡数。
4. **道具/帮助依赖**：使用帮助次数与比例、失败时使用帮助的比例。
5. **时长与步数**：通关/失败平均时长、时长标准差/最大/最小/中位数、剩余步数分布。
6. **关卡难度画像**：所到达最高关卡及所玩关卡的平均通过率/重试次数/时长。

部分特征在"从未失败/从未通关"的子组有缺失（约 16–800 个用户），LightGBM/XGBoost 可原生处理 NaN，无需填充；逻辑回归用中位数填充。

### 3.2 模型
- **逻辑回归（线性基线）**：StandardScaler 标准化 + 中位数填充。
- **LightGBM**：梯度提升树，`num_leaves=63, lr=0.05, subsample/colsample=0.8`。
- **XGBoost**：梯度提升树，`max_depth=6, lr=0.05`。
- **平均集成**：三个基模型概率取平均。
- **栈式集成（Stacking）**：以三个基模型在 dev 上的预测概率为特征，训练逻辑回归元学习器。由于 train 与 dev 用户完全独立，用 dev 拟合元学习器公平合理。

## 四、实验结果与对比

在 `train` 上训练、`dev` 上评估 AUC；随后对 `test` 预测，并与 `Groundtruth` 对照得到测试集 AUC。

| 模型 | dev AUC | 测试集 AUC（对照 Groundtruth） |
|---|---|---|
| LogisticRegression | 0.7990 | — |
| LightGBM | 0.8018 | — |
| XGBoost | 0.8004 | — |
| 平均集成 (LR+LGB+XGB) | 0.8040 | 0.8016 |
| **栈式集成 (LR+LGB+XGB)** | **0.8005** | **0.8049** |

**关键发现：**
- 线性基线已达约 0.80，说明聚合特征本身信息量很强；
- 三种模型 AUC 相当（~0.80），表明特征已基本捕获主要判别信息；
- **集成可进一步增益**：栈式集成在测试集上 AUC ≈ **0.80**，远超 0.65 要求。

**特征重要性**（LightGBM，前 10）：`hours_since_last_active`（最后活跃距观测结束时间）、`max_duration`/`std_duration`/`min_duration`（时长分布）、`duration_per_active_hour`、`mean_duration_fail`、`mean_reststep_succ`、`day1_attempts`、`cleared_rate_of_reached`、`help_rate` 等——印证了"活跃衰减、游玩节奏、卡关与帮助依赖"是流失的核心信号。

## 五、结论

- 最终方案为 **"用户级特征工程 + LR/LightGBM/XGBoost + 栈式集成"**，测试集 AUC ≈ **0.80**，远超 0.65 门槛，方案可行且效果良好。
- 核心经验：非结构化的序列日志通过合理聚合后，用传统的表格模型即可取得很强的效果，而**集成**是进一步提升稳定性的有效手段。

## 六、改进方向

1. **更丰富的特征**：会话切分、连续通关 streak、关卡难度随时间变化轨迹、活跃时段分布等。
2. **时序模型**：用 RNN / Transformer 直接对 `level_seq` 序列建模，自动学习隐式行为模式，可能进一步提升上限。
3. **调参与特征筛选**：用 Optuna 等系统搜索超参，结合特征选择。
4. **更强的集成**：引入随机森林、GBDT、神经网络等更多基模型，并进行加权寻优。
